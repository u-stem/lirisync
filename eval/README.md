# 評価セット（eval）

整列の精度を、手で付けた正解時刻と比べて測ります。音源と歌詞は著作物なのでコミットしません。コミットするのは正解ラベルと評価結果だけです。

## 曲の置き方

```text
eval/songs/<slug>/
├─ labels.txt   # 正解ラベル（コミットする）
├─ lyrics.txt   # 歌詞。1 行が 1 表示行（.gitignore 済み）
├─ audio/       # 音源（.gitignore 済み）
└─ asr/         # ASR の書き起こし。<name>.json と <name>.meta.json（.gitignore 済み）
```

`asr/` の書き起こしは歌詞そのものなので、`lyrics.txt` と同じくコミットしません。

## 正解ラベルの付け方

Audacity のラベルで付け、「ラベルを書き出す」で `labels.txt` に保存します。

- 各行の歌い出しにラベルを置きます。点ラベルでも範囲ラベルでも構いません。範囲ラベルは開始時刻だけを使います
- ラベルの文字列には、歌詞ではなく `lyrics.txt` の行番号（1 始まり）を書きます。ラベルはコミットするので、歌詞そのものを入れないためです
- 精度は 50 ms 程度を目安にします。合格基準が「中央誤差 0.5 秒以内」なので、ラベルの誤差はそれより十分小さくします
- 歌わない行（空行、「（間奏）」など）にはラベルを付けません。ラベルのない行は評価から外れます

読み込みは厳格です。行番号でないラベル、同じ行への 2 つ目のラベル、終了が開始より前の範囲、周波数の選択を含む行は、行番号付きのエラーで止まります。`lyrics.txt` にない行や空行を指すラベルも、エラーにします。

## 指標

- **一致率**：ラベルのある行のうち、整列が開始時刻を出せた行の割合
- **行開始の中央誤差**：一致した行の「予測と正解の開始時刻の差の絶対値」の中央値。全曲の行をまとめてから中央値を取ります
- **繰り返し行の取り違え率**：同じ文面の行（NFKC で揃えて比較）について、予測の開始時刻が自分の正解より、別の出現の正解に厳密に近い行の割合。同じ距離は取り違えに数えません。比べる相手のいない行は数えません
- **行開始の P90**：一致した行の誤差の 90 パーセンタイル（最近順位法）。中央値では見えない裾を測ります
- **粗大誤差率**：一致した行のうち、誤差が 1 秒を超える行の割合。一致しなかった行は一致率の側で数えます
- **沈黙誤差率**：高信頼（既定は 0.8 以上）と出した行のうち、誤差が 1 秒を超える行の割合。信頼度を信じた利用者が確かめない誤りです
- **信頼度の AUROC**：誤差 1 秒以内の行と粗大誤差の行から 1 つずつ選んだとき、前者の信頼度が高い確率。同じ値は半分と数えます。0.5 は当て推量と同じです

信頼度を使う 2 つの指標は、整列器が信頼度を出すときだけ計算します。一致した行の一部にだけ信頼度がある出力と、0 以上 1 以下の数でない信頼度は、整列器の誤りとしてエラーにします。

精度の合格基準は、中央誤差 500 ms 以下かつ一致率 85% 以上です。

## ASR の書き起こしの形式

ワーカーにはまだ ASR がないので（GPU が要ります）、各曲の ASR の単語は `asr/<name>.json` から読みます。形はワーカーのプロトコルの単語と同じです。

```json
{
  "words": [
    { "startMs": 12300, "endMs": 12900, "text": "風が" },
    { "startMs": 12900, "endMs": 13600, "text": "吹く" }
  ]
}
```

- 時刻は 0 以上の整数ミリ秒です。小数や負の値はエラーにします
- 単語は開始時刻の昇順に並べます（同じ開始時刻、重なりは可）。終了が開始より前の単語と、並びの崩れた単語は、何番目の単語かを示してエラーにします
- 上記以外のフィールドはエラーにします
- `text` は書き起こしの出力のまま入れます。Whisper は英単語の先頭に空白を付けます（`" line"`）。この空白を消すと、英語の行が一致しなくなります

## ボーカルを分離する

`lirisync-transcribe` はボーカルだけの音声を読みます。ワーカーの `separate` メソッドで、ミックスの音源からボーカルを取り出せます。外部の分離ツールは要りません。

1. 各曲のミックスを `audio/mix.*` に置きます（拡張子は何でも、1 曲に 1 つ）
2. 分離モデルを取得します

   ```sh
   uv --directory workers/align run python tools/fetch_separator_model.py --dest <dir>
   ```

3. 分離します

   ```sh
   bun run eval:separate --model <dir>/sep-all-int8.onnx
   ```

各曲の `audio/mix.*` から `audio/vocals.wav` を作ります。書き出す形式は 44.1 kHz、2 チャンネルの WAV です。ワーカーは一時ファイルに書いてから置き換えるので、途中で止まっても壊れた `vocals.wav` は残りません。

デコードに ffmpeg を使います。`PATH` に置くか、環境変数 `LIRISYNC_FFMPEG` でパスを指定してください。推論は今のところ CPU だけです。Mac の CPU では、曲の長さの約 2 倍の時間がかかりました（20 秒の音声で約 40 秒）。

| オプション | 内容 |
| --- | --- |
| `--model <path>` | 分離モデルの ONNX ファイル。必須 |
| `--songs-dir <path>` | 曲のディレクトリ。既定は `eval/songs` |
| `--song <slug>` | 分離する曲を絞ります。繰り返して複数指定できます。存在しない slug はエラーです |
| `--input <stem>` | 元にする音声ファイルの名前（拡張子なし、大文字と小文字は区別しない）。既定は `mix`。`vocals` は出力の名前なので指定できません |
| `--overwrite` | 既にある `audio/vocals.wav` を置き換えます。付けないと、あるときはエラーです |
| `--skip-existing` | 既にボーカルのある曲を飛ばします。`--overwrite` とは同時に使えません |

- 既存のボーカルは、`audio/` にある名前（最後の拡張子を除く）が `vocals` のファイルです（大文字と小文字は区別しません）。`lirisync-transcribe` が選ぶファイルと同じ基準です。`vocals.meta.json` の名前は `vocals.meta` なので数えません
- `--skip-existing` なら、拡張子に関わらず既存のボーカルがある曲を飛ばします（その曲のミックスは見ません）
- それ以外で、既存のボーカルが `.wav` でないとき、または複数あるときは、`--overwrite` を付けてもエラーです。利用者のファイルは消さず、`vocals.wav` を並べて置くと書き起こしの側が 2 つ見つけてしまうためです。先に移してください
- 既存の `vocals.wav` があって `--overwrite` がないときはエラーです。`--overwrite` では、そのファイルの実際の名前（`Vocals.WAV` など）に書いて置き換えます
- モデルの存在、各曲のミックスが 1 つだけあること、上の衝突は、ワーカーを起動する前に全曲分を確かめます。そのあとでモデルの SHA-256 を計算します（約 240 MB）
- 曲ごとに `audio/vocals.meta.json` も書きます。キーは camelCase で、元にしたファイル名（`input`）、モデルのファイル名（`model`）とその SHA-256（`modelSha256`）、ワーカーの版（`worker`）を記録します。`vocals.wav` を書く前に書くので、`vocals.wav` があれば分離が終わったものとみなせます。`--overwrite` では、メタ情報を書く前に古い `vocals.wav` を消します。分離が途中で失敗しても、新しいメタ情報と古い音声が並んで残らないようにするためです
- 進捗は標準エラー出力に `[n/N] <slug>: NN% (eta m:ss)` の形で出ます。端末では同じ行を上書きし、端末でないとき（ログなど）は 10 % ごとに 1 行出します。失敗したときは `error: ...` を出して終了コード 1 で終わります。途中で失敗したときは、同じコマンドに `--skip-existing` を付けて再実行すると、終えた曲を飛ばして続きから進めます

## 書き起こしを作る（Windows 機）

`asr/<name>.json` は、評価専用のツール `eval/transcribe` が faster-whisper で作ります。配布版やワーカーには入れません（faster-whisper が PyAV 経由で FFmpeg を、GPU では NVIDIA の CUDA ライブラリを要求し、配布のライセンス方針に合わないため。詳しくは `docs/dependencies.md`）。

各曲の `audio/vocals.*` を書き起こします。`audio/vocals.wav` は「ボーカルを分離する」の手順で作れます。別のツールで分離した `vocals.*` も使えます。`audio/` には、`vocals` という名前（拡張子は何でも）のファイルを 1 曲に 1 つだけ置きます。ボーカルを分離していない音源を使うときは、`audio/mix.*` のように別の名前で置き、`--audio mix` を付けます。

```sh
uv --directory eval/transcribe run lirisync-transcribe --model Systran/faster-whisper-large-v3 --name large-v3
```

全曲を書き起こしてから `bun run eval --asr large-v3` に渡します。書き出す前に、引数、曲、音声ファイル、書き出し先の重複をすべて確かめ、そのあとでモデルを読み込みます。長い推論のあとで入力の誤りに気づくことを避けるためです。

| オプション | 内容 |
| --- | --- |
| `--model <repo id またはパス>` | 使う Whisper のモデル。Hugging Face のリポジトリ ID か、ローカルのディレクトリ。必須 |
| `--name <name>` | 書き出す名前（`asr/<name>.json`）。必須。使える文字は `bun run eval --asr` と同じ |
| `--songs-dir <path>` | 曲のディレクトリ。既定は `../songs`。`uv --directory eval/transcribe` は `eval/transcribe` で動くため、既定でこのリポジトリの `eval/songs` を指します |
| `--song <slug>` | 書き起こす曲を絞ります。繰り返して複数指定できます。存在しない slug はエラーです |
| `--audio <stem>` | 使う音声ファイルの名前（拡張子なし、大文字と小文字は区別しない）。既定は `vocals` |
| `--device <device>` | `auto`、`cpu`、`cuda`。既定は `auto` |
| `--compute-type <type>` | CTranslate2 の計算型。既定は `default` |
| `--beam-size <n>` | ビームの幅。1 以上の整数。既定は 5 |
| `--vad` | 音声区間検出を使います。既定は切です。歌の部分を切り落とすことがあるためです |
| `--overwrite` | 既にある `asr/<name>.json` を置き換えます。付けないと、あるときはエラーです |
| `--skip-existing` | 既に `asr/<name>.json` がある曲を飛ばします。`--overwrite` とは同時に使えません |

- GPU（`--device cuda`、または `auto` で GPU が見つかったとき）には、NVIDIA のドライバと、ctranslate2 が要求する CUDA のライブラリが要ります。必要な版は ctranslate2 の版で変わるので、ここには書きません。[CTranslate2 の導入手順](https://opennmt.net/CTranslate2/installation.html)を見てください。CPU（`--device cpu`）でも動きますが、大きなモデルでは遅くなります
- モデルは初回に Hugging Face のキャッシュへダウンロードされます。2 回目からは再利用します
- 言語は日本語（`ja`）に固定し、単語ごとの時刻を付けます。単語の文字列は、空白を含めて書き起こしの出力のまま `text` に入れます
- 曲ごとに `asr/<name>.meta.json` も書きます。キーはすべて camelCase です。モデル（`model`）、faster-whisper・ctranslate2・av の版（`fasterWhisper`、`ctranslate2`、`av`）、要求したデバイスと計算型（`device`、`computeType`）、実際に使われたもの（`deviceUsed`、`computeTypeUsed`）、ビーム幅（`beamSize`）、VAD の有無（`vad`）、言語（`language`）、使った音声ファイル（`audio`）、揃えた開始の数（`clampedStarts`）を記録します。結果を比べるときの手がかりです
- 進捗、警告、エラーは標準エラー出力に出ます。失敗したときは `error: ...` を出して終了コード 1 で終わります
- 途中で失敗したときは、同じコマンドに `--skip-existing` を付けて再実行すると、書き終えた曲を飛ばして続きから進めます。`asr/<name>.json` は曲の最後に書くので、あれば書き終えたものとみなせます（先に `<name>.meta.json` を書きます。`--overwrite` では、書き始める前に古い `<name>.json` を消します）。設定を変えて取り直すときは付けません
- Whisper の単語の開始時刻が前の単語より戻った場合は、その開始を前の単語の開始に揃え（終了は開始より前にならないようにします）、曲ごとに揃えた数を `warning: <slug>: N word starts clamped` で知らせ、`.meta.json` の `clampedStarts` に記録します。単語の順は変えません。1 曲で揃えた数が多いときは、その書き起こしを疑ってください
- 単語が 1 つもない曲は `warning: <slug>: no words` を出します（終了コードは 0 のままです）。音声が空か、モデルが何も聞き取れなかった可能性があります
- `<name>` は `.meta` で終われません。`<name>.meta.json` と名前がぶつかるためです

## 実行

```sh
bun run eval --asr <name>
```

全曲を `anchor`（整列の第 1 段）に通し、曲ごとと全曲まとめての指標、精度の合格基準の判定を表示します。判定が不合格でも終了コードは 0 です（測定のためです）。エラーのときだけ 0 以外で終わります。ワーカーが 0 以外の終了コードで終わったときは、結果を表示・書き出したうえで、警告を出して終了コード 1 で終わります。

`eval/songs` の下で `.` で始まるディレクトリは、曲として扱いません。

| オプション | 内容 |
| --- | --- |
| `--asr <name>` | 使う書き起こし（`asr/<name>.json`）。必須。英数字、`.`、`_`、`-` だけ使えます |
| `--songs-dir <path>` | 曲のディレクトリ。既定は `eval/songs` |
| `--song <slug>` | 評価する曲を絞ります。繰り返して複数指定できます。存在しない slug はエラーです |
| `--out <path>` | 結果を JSON で書き出します（`{ asr, worker, report }`。`--refine` のときは `refine`、`--perturb` のときは `perturbation` も） |
| `--perturb` | 歌詞を壊して整列し直す摂動テストを、通常の評価のあとに実行します。既定はオフで、付けないと通常の出力は変わりません。「摂動テスト」を見てください |
| `--refine <model dir>` | 第 2 段（強制整列）も測ります。「第 2 段を測る」を見てください |
| `--spelling surface\|kana` | 第 2 段で強制する文字。`--refine` が要ります |
| `--margin-ms <n>` | 第 2 段で窓の前後に足す余白。`--refine` が要ります |

`--refine` を付けないときは第 1 段だけを測ります。第 1 段の信頼度は一致率（行の文字のうち ASR と完全に一致した割合）です。そのため、信頼度を使う 2 つの指標（沈黙誤差率と AUROC）は第 1 段では参考値です。第 2 段の信頼度は「第 2 段を測る」にあります。

## 第 2 段を測る

第 2 段は、第 1 段が見つけた行の窓の中で、歌詞を文字 CTC モデルに強制整列して、行の開始と終了を決めます（ワーカーの `refine`）。`--refine` を付けると、第 1 段のあとに曲ごとに `refine` を呼び、第 1 段と第 2 段の報告を並べて出します。

1. 整列モデルを取得します

   ```sh
   uv --directory workers/align run python tools/fetch_aligner_model.py --dest <dir>
   ```

2. 各曲の `audio/vocals.*` を用意します（「ボーカルを分離する」を見てください）。第 2 段はボーカルの音声を読みます
3. 実行します

   ```sh
   bun run eval --asr <name> --refine <dir>
   ```

| オプション | 内容 |
| --- | --- |
| `--refine <model dir>` | 整列モデルのディレクトリ（`model.int8.onnx` と `vocab.json` を含む）。付けたときだけ第 2 段を実行します |
| `--spelling surface\|kana` | 強制する文字。`surface` は歌詞の字面のまま、`kana` は辞書の読みをひらがなにしたもの。既定は `surface` |
| `--margin-ms <n>` | 各行の窓（第 1 段が見つけた区間）の前後に足す余白。0 以上の整数のミリ秒。既定は 1000 |

- `--spelling` と `--margin-ms` を `--refine` なしで指定するとエラーです
- ワーカーを起動する前に、モデルのディレクトリに `model.int8.onnx` と `vocab.json` があること、全曲に `audio/vocals.*` がちょうど 1 つあること（名前の最後の拡張子を除いた部分が `vocals`、大文字と小文字は区別しない。「ボーカルを分離する」と同じ基準です）を確かめます
- 第 1 段で `anchor` になった行だけが窓を持ちます。窓は第 1 段の開始から終了までで、ほかの行は窓なしで `refine` に渡します
- **第 2 段の予測**
  - `refined` の行は、第 2 段の開始時刻を使います。信頼度は `exp(logRatio)`（0 から 1。`logRatio` は強制した経路の 1 フレームあたりの対数尤度比で、0 に近いほど音声が支持しています）です
  - `refined` でなく、第 1 段が `anchor` だった行は、第 1 段の開始時刻に戻し、信頼度を 0 にします。第 2 段で確かめられなかった行を、高信頼に数えないためです
  - 第 1 段が位置を出さなかった行は、開始なし（不一致）のままです
- この信頼度は暫定です。誤差との関係で較正していないので、沈黙誤差率と AUROC は参考値として読んでください
- 報告は第 1 段、第 2 段の順に出ます（見出しで区別します）。続けて、曲ごとと全体の状態ごとの行数（`refined`、`no_window`、`no_text`、`too_long`、`too_short`）と、モデルの語彙にない文字の数（`skipped chars`）の合計を出します
- `--out` の JSON には `refine: { spelling, marginMs, report, statuses }` が足されます。`report` は第 2 段の予測の報告（第 1 段と同じ形）、`statuses` は全体（`overall`）と曲ごと（`songs`）の行数です。歌詞の文面は入れません。`--refine` なしの出力と JSON は変わりません
- `refine` の途中で失敗したときは、第 1 段の報告を表示し、`--out` にも書いたうえで（`refine` は入りません）、エラーで終わります。`--perturb` を付けていても摂動テストは走らず、標準エラー出力に `note: --perturb is skipped because stage 2 failed` を出します
- 推論は今のところ CPU だけで、遅くなります。曲ごとの所要時間は標準エラー出力に出ます
- `--perturb` と同時に指定したときも、摂動は第 1 段だけで行います（標準エラー出力に 1 行の注記が出ます）。第 2 段の摂動は未対応です

## 摂動テスト

第 2 段（強制整列）を採用する条件の 1 つは、歌詞の間違いが広がらないことです。「摂動による巻き添えが 1 行以内」を、第 1 段の今の値（基準）と第 2 段を入れたあとの値で比べるために測ります。

摂動は、利用者の歌詞に実際にある 3 種類の編集です。ラベルのある行（`collapse` は繰り返しのブロック）ごとに、編集した歌詞を同じ ASR の単語で整列し直します。

| 種類 | 編集 |
| --- | --- |
| `delete` | ラベルのある行を 1 行消す（歌詞の書き漏らし） |
| `duplicate` | ラベルのある行の直後に同じ行をもう 1 行足す（余分な行） |
| `collapse` | 直後に繰り返される 1〜4 行のブロックの 2 回目を消す（「×2」と書いて展開していない繰り返し） |

- 編集で触れた行（`delete` は消した行、`duplicate` は元の行、`collapse` は 2 回分のブロックの行）は数えません。後ろの行は編集の分だけ番号がずれるので、元の行番号に対応づけて比べます
- **巻き添え**は、数える行のうち、基準では良かった（開始が出ていて、誤差が 1 秒以内）のに、摂動のあとでは良くない行です。逆に良くなった行は巻き添えに数えず、`improved` として別に数えます
- 種類ごとに、摂動の数、巻き添えが 1 行以上の摂動の数（`with collateral`）、巻き添えが 2 行以上の摂動の割合（`over one`）、巻き添えの平均と最大、`improved` の合計を出します。採用の基準は `over one` が 0 %、つまり巻き添えが 1 行以内であることです
- `collapse` は、歌詞に直後の繰り返しのブロックがあるときだけ摂動ができます。なければ摂動の数は 0 で、割合は「—」です
- 摂動のたびにワーカーの `anchor` を 1 回呼びます。数は、標準エラー出力の最初の行（`N perturbations`）と、曲ごとの進捗行（かかった時間つき）で分かります
- `--out` の `perturbation` には、種類ごとの集計（`kinds`）と、曲ごとの摂動の一覧（`songs`）が入ります。一覧の各要素は `kind`、`at`（元の歌詞で編集が始まる行）、`span`（編集が及ぶ行数。`delete` と `duplicate` では 1）、`collateral`、`collateralLines`（巻き添えになった元の行番号）、`improved` です。歌詞の文面は入れません。`collapse` では、`at` は繰り返しの 1 回目のブロックの先頭行、`span` はブロックの行数です。消すのは `at + span` 行目から始まる 2 回目のブロックで、数えないのは両方のブロックの `2 × span` 行です
- 摂動した歌詞では、ラベルのある行が「歌わない行」になっても止めません（行にラベルが付いているのではなく、対応づけているためです）
- 摂動の途中で `anchor` が失敗したときは、通常の評価の結果を表示し、`--out` にも書いたうえで（`perturbation` は入りません）、エラーで終わります
